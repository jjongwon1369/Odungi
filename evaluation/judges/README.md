시스템 이름을 가리고 Groundedness, Structural Integrity, Identifier Accuracy, Cross-document Synthesis 평가.

# 채점 기준 v1 (평가분석 담당 박종원, 2026-09-26)

## 1. 무엇을 어떻게 채점하나

| 채점 방식 | 대상 문항 | 비용 | 하는 일 |
|---|---|---|---|
| **자동 채점** | 34문항 (식별자가 정답에 있는 문항) | 0원 | 답변 속 ID·이름을 원본 정답표와 코드로 대조 |
| **심판자 LLM** | 21문항 (의미형·다중홉 서술 15 + 심판 전용 6) | 구독 | 아래 루브릭으로 채점 |

- 두 방식이 겹치는 15문항은 식별자는 자동으로, 설명의 질은 심판자가 봅니다.
- 대조군 4문항은 코퍼스에 없는 내용을 묻습니다. **모른다고 답해야 정답**이고, 지어내면 환각으로 기록합니다.

## 2. 심판자 루브릭 (레포에 정한 4축)

| 축 | 점수 | 기준 |
|---|---|---|
| Groundedness (근거성) | 0–2 | 답변의 주장이 인용한 문서에 실제로 있는가 |
| Structural Integrity (구조 보존) | 0–2 | 조건·필수/선택·피처 의존 같은 구조를 잃지 않았는가 |
| Identifier Accuracy (식별자) | 자동 | 자동 채점 결과를 그대로 사용 |
| Cross-document Synthesis (문서 간 종합) | 0–2 | 여러 문서(XML·코드·기기 정의)를 맞게 엮었는가. 한 문서로 끝나는 문항은 N/A |
| 정답 여부 | 정답 / 부분 / 오답 | 평가 담당이 보관한 정답 메모와 비교 |
| 환각 | 있음 / 없음 | 코퍼스에 없는 내용을 사실처럼 말했는가 |

## 3. 블라인드 규칙

- 심판자에게는 **질문 · 정답 메모 · 답변 · 인용 문서**만 줍니다. 시스템 이름(A/B/C)과 모델 이름은 지웁니다.
- 답변 순서를 무작위로 섞고, 답변 ID도 무작위 문자열로 바꿉니다.
- 심판 프롬프트는 실험 전에 고정합니다 (`judge_prompt_v1.md`).

## 4. 채점 분량

참가자 LLM 7개 × 시스템 3개 × 40문항 = 한 번 돌릴 때 **답변 840개**.

| 항목 | 반복 1회차 | 반복 3회 전체 |
|---|---|---|
| 전체 답변 | 840 | 2,520 |
| 자동 채점 | 840 (전부) | 2,520 (전부) |
| 심판자 채점이 필요한 답변 | 441 | 1,323 |

**심판자는 반복 1회차만 채점합니다.** 2·3회차는 자동 채점만 해서 반복 간 흔들림을 봅니다. 1회차 441개를 심판 2개가 각각 채점하면 **882건**입니다.

## 5. 분담표

| 역할 | 담당 | 도구 | 분량 |
|---|---|---|---|
| 자동 채점 실행 | 박종원 | 채점 스크립트 | 2,520건 |
| 심판자 ① Claude | 박종원 | Claude Max 구독 · Opus 5.5 · Claude Code로 자동 실행 | 441건 |
| 심판자 ② GPT | 박종원 | ChatGPT 구독 · Codex CLI로 자동 실행 | 441건 |
| 사람 검산 | 전원 (1인 약 11건) | 블라인드 시트 | 심판 결과 중 무작위 44건 (10%) |

- **사람 검산**은 심판자 LLM이 제대로 채점했는지 확인하는 단계입니다. 시스템 이름을 가린 시트로 한 사람당 11건 정도를 봅니다. 자기가 만든 시스템의 답인지 모르게 섞습니다.
- 두 심판의 판정이 갈리면 사람 검산 대상에 우선 포함합니다.
- 심판자가 Claude와 GPT라서, 같은 회사 모델의 답변을 후하게 주는지도 따로 확인해 보고합니다.
