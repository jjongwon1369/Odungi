# Temperature Control

### 클러스터와 초기 구성

`chip::app::Clusters`의 `TemperatureControlCluster`는 `DefaultServerCluster`를 상속한다. 생성자는 `EndpointId`, `BitFlags<TemperatureControl::Feature>`, `StartupConfiguration`을 받는다.

`StartupConfiguration`은 다음 필드로 구성된다. 모든 필드는 `{}`로 초기화된다.

| 필드 | 타입 |
|---|---|
| `temperatureSetpoint` | `int16_t` |
| `minTemperature` | `int16_t` |
| `maxTemperature` | `int16_t` |
| `step` | `int16_t` |
| `selectedTemperatureLevel` | `uint8_t` |

생성자는 `VerifyOrDie`로 다음 조건을 검사한다.

- `Feature::kTemperatureNumber`가 활성화된 경우:
  - `Feature::kTemperatureLevel`이 비활성화되어야 한다.
  - `mMinTemperature`는 `kMinTemperatureRange`인 `-27315` 이상, `kMaxTemperatureRange`인 `32766` 이하여야 한다.
  - `mMaxTemperature >= mMinTemperature + 1`이어야 한다.
  - `mTemperatureSetpoint`는 `mMinTemperature` 이상, `mMaxTemperature` 이하여야 한다.
  - `Feature::kTemperatureStep`도 활성화되어 있으면 `mStep`은 `kMinStep`인 `1` 이상, `mMaxTemperature - mMinTemperature` 이하여야 한다.
- `Feature::kTemperatureLevel`이 활성화된 경우:
  - `mSelectedTemperatureLevel`은 `kMaxSelectedTemperatureLevel`인 `31` 이하여야 한다.

`mFeatures`, `mMinTemperature`, `mMaxTemperature`, `mStep`은 `const` 멤버이다. `mDelegate`는 정적 멤버이며 초기값은 `nullptr`이다.

### 등록 및 수명 관리

`CodegenIntegration.cpp`는 다음 크기로 `gServers`를 구성한다.

- `kTemperatureControlFixedClusterCount`: `TemperatureControl::StaticApplicationConfig::kFixedClusterConfig.size()`
- `kTemperatureControlMaxClusterCount`: `kTemperatureControlFixedClusterCount + CHIP_DEVICE_CONFIG_DYNAMIC_ENDPOINT_COUNT`
- 저장 형식: `LazyRegisteredServerCluster<TemperatureControlCluster>`

`IntegrationDelegate::CreateRegistration`은 `optionalAttributeBits`와 `featureMap`을 사용하여 구성 정보를 처리한다.

1. `Feature::kTemperatureNumber`가 활성화되면 `TemperatureSetpoint`, `MinTemperature`, `MaxTemperature`의 존재와 `GetDefault` 성공 여부를 확인한다.
2. 여기에 `Feature::kTemperatureStep`이 활성화되어 있으면 `Step`에도 같은 검사를 수행한다.
3. `Feature::kTemperatureLevel`이 활성화되면 `SelectedTemperatureLevel`의 존재와 기본값을 확인하고, `SupportedTemperatureLevels`의 존재를 확인한다.
4. 읽은 값으로 `TemperatureControlCluster::StartupConfiguration`을 구성하여 `gServers[clusterInstanceIndex].Create`를 호출한다.

| 함수 | 동작 |

### 값 변경 API

#### `SetTemperatureSetpoint`

다음 순서로 검사한다.

1. `Feature::kTemperatureNumber`가 없으면 `CHIP_IM_GLOBAL_STATUS(InvalidInState)`를 반환한다.
2. 값이 `mMinTemperature`부터 `mMaxTemperature`까지의 범위를 벗어나면 `CHIP_IM_GLOBAL_STATUS(ConstraintError)`를 반환한다.
3. `Feature::kTemperatureStep`이 활성화되어 있으면 다음 조건을 검사한다.

```cpp
(temperatureSetpoint - mMinTemperature) % mStep == 0
```

조건을 만족하지 않으면 `CHIP_IM_GLOBAL_STATUS(ConstraintError)`를 반환한다. 검증 후 `SetAttributeValue`로 `mTemperatureSetpoint`를 변경하고 `CHIP_NO_ERROR`를 반환한다.

#### `SetSelectedTemperatureLevel`

다음 순서로 검사한다.

1. `Feature::kTemperatureLevel`이 없으면 `CHIP_IM_GLOBAL_STATUS(InvalidInState)`를 반환한다.
2. `mDelegate`가 `nullptr`이면 `CHIP_IM_GLOBAL_STATUS(NotFound)`를 반환한다.
3. `selectedTemperatureLevel < mDelegate->Size()`를 만족하지 않으면 `CHIP_IM_GLOBAL_STATUS(ConstraintError)`를 반환한다.
4. `mDelegate->Reset(mPath.mEndpointId)`를 호출한 뒤 `SetAttributeValue`로 `mSelectedTemperatureLevel`을 변경한다.

성공하면 `CHIP_NO_ERROR`를 반환한다. 이 함수에서는 `Size()` 검사가 `Reset`보다 먼저 수행된다.

#### 조회 및 통합 API

클래스는 `GetTemperatureSetpoint`, `GetSelectedTemperatureLevel`, `GetStep`, `GetMinTemperature`, `GetMaxTemperature`를 제공한다.

`chip::app::Clusters::TemperatureControl`의 통합 API는 다음과 같다.

```cpp
TemperatureControlCluster * FindClusterOnEndpoint(EndpointId endpointId);

CHIP_ERROR SetTemperatureSetpoint(EndpointId endpointId, int16_t temperatureSetpoint);
CHIP_ERROR SetSelectedTemperatureLevel(EndpointId endpointId, uint8_t selectedTemperatureLevel);

SupportedTemperatureLevelsIteratorDelegate * GetDelegate();
void SetDelegate(SupportedTemperatureLevelsIteratorDelegate * delegate);
```

Endpoint 기반 두 설정 함수는 클러스터를 찾지 못하면 `CHIP_ERROR_INVALID_ARGUMENT`를 반환하고, 찾으면 해당 인스턴스의 설정 함수를 호출한다. `GetDelegate`와 `SetDelegate`는 클래스의 정적 함수로 위임한다.

### `SupportedTemperatureLevels` 제공

`SupportedTemperatureLevelsIteratorDelegate`는 다음 인터페이스를 제공한다.

| 함수 | 동작 |
|---|---|
| `Reset(EndpointId endpoint)` | `mEndpoint`를 설정하고 `mIndex`를 `0`으로 초기화 |
| `Size()` | 목록의 전체 크기를 반환하는 순수 가상 함수. 반환형은 `uint8_t` |
| `Next(MutableCharSpan & item)` | 다음 항목을 제공하는 순수 가상 함수. 반환형은 `CHIP_ERROR` |

`ReadAttribute`에서 목록을 읽는 흐름은 다음과 같다.

1. `mDelegate == nullptr`이면 `EncodeEmptyList`를 호출한다.
2. 그렇지 않으면 요청의 Endpoint로 `Reset`을 호출한다.
3. `kMaxTemperatureLevelStringSize`가 `32`인 버퍼를 사용한다.
4. `Next(item) == CHIP_NO_ERROR`인 동안 각 항목을 인코딩한다.
5. 항목 인코딩 오류는 반환하지만, `Next`가 반환한 비성공 값은 목록 반복 종료로 처리한다.

### `SetTemperature` 처리

`AcceptedCommands`는 `Commands::SetTemperature::kMetadataEntry`를 등록한다.

`InvokeCommand`는 `Commands::SetTemperature::Id`에 대해 `Commands::SetTemperature::DecodableType`으로 입력을 디코딩한 뒤 `HandleSetTemperature`를 호출한다. 다른 명령에는 `Protocols::InteractionModel::Status::UnsupportedCommand`를 반환한다.

| 활성 기능 | 필수 입력 검사 | 설정 함수 |
|---|---|---|
| `Feature::kTemperatureNumber` | `targetTemperature.HasValue()` | `SetTemperatureSetpoint` |
| `Feature::kTemperatureLevel` | `targetTemperatureLevel.HasValue()` | `SetSelectedTemperatureLevel` |

`HandleSetTemperature`의 상태 반환은 다음과 같다.

| 조건 | 반환 상태 |
|---|---|
| 활성 기능에 필요한 입력이 없음 | `Status::InvalidCommand` |
| 설정 함수가 `CHIP_IM_GLOBAL_STATUS(ConstraintError)` 반환 | `Status::ConstraintError` |
| 레벨 설정 함수가 `CHIP_IM_GLOBAL_STATUS(NotFound)` 반환 | `Status::NotFound` |
| 그 밖의 설정 오류 | `Status::InvalidInState` |
| 처리 성공 | `Status::Success` |

### 스펙과 구현의 제약 표현 차이

- 스펙의 `SupportedTemperatureLevels`는 최대 `32`개 항목, 각 문자열은 `maxLength="16"`이다. SDK XML은 `length="32"`를 선언하며, 구현은 크기 `32`의 문자열 버퍼를 사용한다. 제공된 읽기 루프에는 항목 수 `32` 또는 문자열 길이 `16`을 직접 검사하는 코드가 없다.
- 생성자는 `SelectedTemperatureLevel`의 최댓값 `31`을 검사하지만, `SetSelectedTemperatureLevel`은 `mDelegate->Size()`를 기준으로 검사한다.
- 생성자는 초기 `TemperatureSetpoint`의 범위를 검사하지만, 단계 정렬 조건은 `SetTemperatureSetpoint`에서 검사한다.
- 생성자의 `kMaxTemperatureRange` 검사는 `mMinTemperature`에 적용된다. `mMaxTemperature`에는 `mMinTemperature + 1` 이상인지 검사하는 코드가 제공되어 있다.
