# System C — 위키 검증

컴파일된 위키가 원본 코퍼스의 정보를 보존하고 있는지, 그리고 설계한 주입 방식이
모델 context 안에 들어갈 수 있는지 검증한다.

## 구성

- `validate_wiki.py` — 검증 스크립트

## 검사 항목

### 1. 출처 검증
모든 페이지가 `source_paths` 와 `commit_hash`(SSOT) 프론트매터를 갖는지 확인한다.
출처 없는 페이지는 실험 결과의 추적 가능성을 깨뜨리므로 실패로 처리한다.

### 2. 식별자 보존 검증
페이지의 `source_paths` 로 원본 파일을 역추적해, 원본에 있던 식별자
(클러스터·속성 ID `0x....`, XML `name` 속성값)가 컴파일된 페이지에 그대로
남아있는지 대조한다. 보존율이 60% 미만인 페이지는 정보 누락으로 경고한다.

식별자는 컴파일 과정에서 LLM 이 바꾸거나 빠뜨리기 가장 쉬운 값이면서, 기술문서
질의에서 정답 판정의 기준이 되는 값이라 별도로 검사한다.

### 3. 전체 토큰 수 / context 수용 가능 여부
위키 전체의 추정 토큰 수를 계산하고, 질문·지시문 여유분을 더한 값이 모델
context window 에 들어가는지 판정한다. **정적 전체주입 방식을 쓸 수 있는지를
결정하는 근거 값**이며, 한도를 초과하면 설계 재검토가 필요하다.

## 사용법

리포 루트에서 실행한다.

```bash
python3 systems/system_c_llm_wiki/validation/validate_wiki.py
```

검증 실패(프론트매터 누락 또는 식별자 보존율 미달) 시 exit code 1 을 반환한다.
